# Three annotated surfaces — review and implementation direction

Scope: the existing Orion Next.js dashboard, limited to the filter panel, performance dialog and match detail. Source: user annotations plus live screenshots captured during this run in the in-app browser at1740×1031.

1. Filters — usable but visually compressed. `01-filters-before.jpg`: the input, labels, competition, season, minutes and reset compete on one thin horizontal line; most control values are tiny. Selected scope is not visually distinguishable from the default state. Preserve explicit accessible labels and immediate URL-backed filtering. Improve field sizes, label/value separation and applied filter chips; keep a compact count/reset footer. Reflow fields on mobile, retain native keyboard support.
2. Player dialog — flat hierarchy and too many identical boxes. `02-player-before.jpg`: name, avatar and provider rating are visually detached; every metric, including unknown goalkeeper metrics on an outfield player, has equal emphasis. Keep the real source rating and complete observations. Present identity and observed rating first; four match KPIs, then grouped attack, distribution, defense and goalkeeper metrics, including explicit unknowns. Keep actions in a footer and the close control always discoverable. Verify native dialog focus, Escape and mobile scrolling.
3. Match — wrong order and excessive vertical travel. `03-match-before.jpg`: a global season/league filter and appearance export precede the match; score and chart are mixed in one full-width card, then an ungrouped long list of paired numbers without team column headers, then forty players before the detailed archive. Preserve every collected metric and all 13 archive families. Introduce a dedicated scoreboard, compact observed match KPIs, primary section navigation, an overview with side-by-side comparison/chronology and leading performers, a shot analysis view, team-separated players, early compositions and complete grouped statistics. Move raw/provider-specific detail behind deliberate selection. Keep original unavailable values and source-quality warnings.

Strengths preserved: real club/player imagery, canonical JSON records, charts with real selectable observations, labeled controls, Next links, explicit missing values and archived source payloads.

Accessibility risks visible: tiny/low-prominence secondary text, cramped controls and excessive scroll. Screenshots do not establish WCAG compliance. Validate keyboard focus, target sizing, labels, selected state and390px overflow in the resulting workflows. Screen-reader testing and a complete contrast audit remain outside this scoped pass.

After implementation, screenshots and actual workflow results are recorded beside this file. This is a scoped redesign, not a change to the rest of the site or the data model.

Implemented review: all three annotated surfaces now meet the scoped acceptance. Filters have readable labeled controls and removable applied state; the player dialog has a coherent portrait/rating hierarchy and grouped observations; match analysis starts with the scoreboard and separates the six major tasks into navigable tabs. All37 source statistics and all 13 archive families remain accessible. Desktop/mobile screenshots were inspected, and keyboard/modal behavior plus production routes were exercised. Two real interaction defects found during verification (rapid filter state and dialog focus return) were fixed and rechecked.

The final build and all 80 existing tests pass. Captured development/production browser diagnostics contain no warnings or errors. Canonical data is unchanged, source HTML and obsolete dist directories are absent, and the local preview remains running.
